# MolDynStudio user manual

Last updated: 27 October 2026. This manual describes the accompanying MolDynStudio v1.3.0 source tree. Controls introduced in this revision may be absent from older installers. The validation record tracks the [MD Setup → MD Run review](VALIDATION_REPORT.md#md-setup--md-run-review--27-october-2026), [integrated 3D viewer](VALIDATION_REPORT.md#integrated-3d-viewer--27-october-2026), and [analysis links to 3D](VALIDATION_REPORT.md#analysis-points-linked-to-3d--27-october-2026) separately.

MolDynStudio prepares supported molecular systems, executes a four-stage GROMACS simulation, and provides tools for trajectory analysis and inspection. The procedures below distinguish files that were generated by a calculation from settings that were only previewed. A completed calculation establishes that the requested operation finished; scientific interpretation still depends on the model, sampling, and analysis protocol. The simulation engine should be cited as GROMACS, together with its installed version [1].

## 1. Choose a supported workflow

| Starting material | Supported route | Conditions |
| --- | --- | --- |
| Protein structure | MD Setup, then MD Run | All residues must have parameters in the selected protein force field. |
| PDB requiring structural review | MD Setup, then Inspect / repair structure | Review a separate candidate before adopting it. Coordinate repair does not supply parameters for covalent adducts or modified residues. |
| Protein plus a separate, noncovalent ligand | MD Setup with an AMBER-family protein force field and ACPYPE/GAFF2 | The ligand must have valid chemistry, a defined protonation state, and coordinates in the same frame as the protein. |
| Protein plus a noncovalent ligand under CHARMM36m | MD Setup with SwissParam MATCH and local ParmEd conversion | Supply one reviewed, explicitly hydrogenated MOL2 molecule. New remote parameterization requires upload consent; a verified matching cache can be reused. |
| Noncovalent ligand copies already present in a complex PDB | CHARMM36m with Use all ligand poses from the protein/complex PDB | The MOL2 defines one chemical identity; every matching PDB residue supplies its own heavy-atom coordinates. Explicitly identify any extra compounds to exclude. |
| A structure without a trajectory | View > 3D structures and trajectories, or MD Setup > Inspect structure in 3D | One coordinate frame from a readable PDB/GRO or compatible TPR; no simulation time or MD-frame export. |
| Existing topology and trajectory | Load System or Analysis | Atom identity, order, and count must agree. File existence alone does not establish compatibility. |
| A selected protein-ligand trajectory frame | Analysis, then the frame inspector and DockLens export | Receptor and ligand must be selected from the same frame and reviewed for periodic boundary artifacts. |

Automatic preparation does not cover covalent protein-ligand adducts or general metal coordination parameterization. The CHARMM ligand route supports a restricted, isolated-ligand MATCH topology; it is not a general importer for arbitrary CGenFF files or covalent patches. A metal-containing ligand, heme complex, unusual cofactor, membrane assembly, or modified residue can require a separately validated model. Do not remove chemically necessary atoms merely to make preparation succeed. System composition, protonation, force-field applicability, and sampling requirements should be established before production MD [12].

The AMBER99SB-ILDN, AMBER14SB, CHARMM36m, and OPLS-AA labels refer to different force fields. Their parameter sets are not interchangeable. Cite the force field actually used, retain its files, and report the water and ion models. Relevant protein force-field papers are listed in references [5–7, 14].

## 2. Install and check the environment

### 2.1. Understand the two execution environments

The desktop interface runs in a local Python/Qt environment or a packaged application. External scientific commands use a separate Conda environment, named `moldynstudio` by default. On Windows, those external commands run through WSL2; on Linux, they run natively. Python trajectory analyses, the frame inspector, and structure repair require their Python libraries in the environment that runs the desktop interface. Installing a library inside WSL alone does not make it importable by Windows Python.

Sequence mapping uses Biopython. Building missing residues or heavy atoms also requires PDBFixer and OpenMM in the application's Python environment; the current GUI requirements include these dependencies. The repair dialog reports whether the local modeling backend is available. Reconstruction runs offline in a separate native process, using OpenMM's CPU platform when available and its Reference platform otherwise. Engine requests, responses, and logs are retained. Conservative record edits remain available without the modeling backend. This local coordinate reconstruction does not invoke the GROMACS production workflow.

The CHARMM ligand adapter requires ParmEd 4.3.1 in the application's Python environment. When ligand poses are taken from a complex PDB, Open Babel in the configured scientific environment generates hydrogen coordinates for each pose. The protein force-field archive remains local after explicit installation; an uncached ligand requires a separate, consented request to the public SwissParam service. No protein structure is included in that ligand request.

The supplied [environment specification](../../environment.yml) records the scientific dependency constraints. A Conda environment file is not an exact lockfile: preserve the resolved package versions for each study. The GUI [requirements](../../requirements.txt) describe a separate set of dependencies.

The GUI requires Python 3.11 or newer. New scientific environments use GROMACS 2025.4, whose TPR format can be read by MDAnalysis 2.10. MDAnalysis 2.10 does not read the GROMACS 2026 TPR format; see the [reader compatibility table](https://docs.mdanalysis.org/2.10.0/documentation_pages/topology/TPRParser.html). Existing environments are not automatically downgraded. Resume existing simulations with their original compatible GROMACS backend and preserve their recorded versions.

For an existing newer TPR, either install a released reader that explicitly supports its format or create a separate matching structural topology with the GROMACS version that produced it. For example, `gmx editconf -f md.tpr -o analysis_topology.pdb -conect` exports a PDB with connectivity; see the [GROMACS command documentation](https://manual.gromacs.org/2026.3/onlinehelp/gmx-editconf.html). Select that PDB explicitly for coordinate analysis and the frame inspector, verify atom count/order, and retain the original TPR for GROMACS QC and MM-PBSA. PDB cannot preserve force-field partial charges, bond orders or repartitioned atomic masses. This conversion therefore does not support charge-dependent hydrogen-bond assignment or reproduce mass-weighted observables from a modified-mass model. Do not replace the original topology or trajectory.

### 2.2. Windows

1. Install or extract the Windows application. Preserve the complete distribution if files accompany the executable.
2. Start MolDynStudio. The launcher checks WSL2, the Conda environment, and the selected GROMACS executable.
3. If virtualization is disabled, follow the launcher's BIOS/UEFI instructions. WSL2 requires hardware virtualization and the Windows Virtual Machine Platform feature.
4. Choose **Install WSL2** when needed. Complete Windows' installation prompts, restart if requested, and initialize the Linux distribution.
5. Return to the launcher and choose **Re-check**. Choose **Create env** if the scientific environment is missing. The installation requires network access and may take several minutes.
6. Inspect the installation log. Re-check until the launcher reports the required components as available, then choose **Begin**.
7. Open **Preferences** and verify the Conda environment, GROMACS binary, CPU cores, and GPU mode.

For a source checkout, the WSL helper can also be started from an administrator PowerShell window:

```powershell
.\install_wsl.ps1
```

If Conda is already installed inside WSL, the scientific environment can be created from that shell. Change to the source directory using its Linux path, then run:

```bash
conda env create -f environment.yml
conda activate moldynstudio
gmx --version
```

Use a writable local project directory such as `C:\MD\study\rep01`. The application translates drive-qualified Windows paths for WSL commands. UNC/network paths are not supported by that bridge. Keep active simulations outside folders whose synchronization or cleanup could alter files while GROMACS is writing them.

### 2.3. Linux

1. Use the supplied Linux installer or install the GUI from the source checkout.
2. For the installer, make the downloaded `.run` file executable and execute that exact file. The installer adds a desktop entry and a `moldynstudio` launcher under `~/.local/bin`.
3. Start MolDynStudio and use **Create env** if the scientific Conda environment is missing.
4. Verify the selected executable and Conda environment in the launcher and Preferences.
5. If Qt reports an XCB/OpenGL platform error, install the distribution's required Qt platform libraries. The repository [installation guide](../../README_GROMACS_Analysis_Studio_v11.md) lists the Ubuntu packages.

For source execution, create a Python virtual environment, activate it, and run:

```bash
python -m pip install -r requirements.txt
python main.py
```

Use a supported Python version with available dependency wheels; the supplied scientific environment uses Python 3.11. The launcher still checks scientific dependencies. Installing GUI requirements alone does not install GROMACS or AmberTools.

### 2.4. Preferences and diagnostics

1. Open **File > Preferences**, the toolbar **Preferences**, or **Settings > Open preferences**. These routes edit the same settings.
2. Leave the GROMACS path on `auto` for environment-based discovery, or specify the executable to use. On Windows, use the path expected inside WSL for an external Linux scientific tool.
3. Set **Conda environment** to the environment containing that tool.
4. Set **Cores for MD** to an appropriate number for the available machine.
5. Select the GPU mode. **Auto** follows the capabilities of the selected GROMACS build. A working graphics driver does not imply that this GROMACS build supports GPU execution.
6. Save. Confirm the executable/version diagnostics before a long run.

The interface currently provides English text and a light theme. Controls should not be interpreted as evidence of a complete Portuguese translation or an independently supported dark theme.

### 2.5. Run a local runtime self-check

Use the self-check when diagnosing a new installation, an import failure, or a native-library crash. For a source checkout with its GUI environment active, run:

```bash
python main.py --self-check runtime-check.json
```

For a Windows distribution, run the executable from its installed folder:

```powershell
.\MolDynStudio.exe --self-check .\runtime-check.json
```

The command writes the requested JSON report and a matching `.log` file. Its six checks exercise MDAnalysis and MDTraj distances, PDBFixer reading, one OpenMM CPU integration step, ParmEd topology writing, and offscreen construction of the application pages. The native work runs in an isolated process. Exit code zero and `status: passed` require every check to finish successfully; an incomplete report or native crash is a failure.

Inspect the named failed check and retain both files when reporting a problem. This diagnostic does not contact SwissParam, run the external GROMACS pipeline, or validate a scientific model. A passing self-check is therefore separate from successful system preparation and MD.

## 3. Navigate and save a project

The main preparation route is **MD Setup → MD Run → Analysis → Results Viewer → Reports & Export**. An existing trajectory can enter through **Load System**. Workflow guidance describes the next action, and the run log records messages from connected modules. The **View** menu can show or hide these panels.

### 3.1. Create a session

1. Choose **New project**. Complete or stop active operations first.
2. On **Project**, enter a name and study notes where needed. Project templates and configuration previews organize settings; they do not launch scientific calculations.
3. In **MD Setup**, select a dedicated project folder. Use a separate folder for each independent replicate and parameterization variant.
4. Choose **Save project** and save the `.mds` file beside the project folder, or inside it.

An `.mds` file stores interface state and references to a prepared project. It does not embed a trajectory or replace the simulation folder. Automatic session saving occurs periodically for an already saved session; explicitly save after important changes. Preserve both the `.mds` file and the referenced data.

MD Setup choices are saved with the session, including edits made after preparation. Reopening the session compares those choices with the prepared snapshot in `moldynstudio_run.json`; saving or reopening does not apply a pending draft to the prepared files. New sessions restore the initial setup controls without deleting the previous project's files. Ligand chemistry confirmation and upload consent must be reviewed again; saved state does not authorize a new upload.

The integrated 3D panel saves source paths, receptor/ligand selections, the requested zero-based frame index, and visibility. Reopening restores those choices without reading coordinates: choose **Load 3D view** after checking the paths. Periodic-boundary confirmation and a previously exported DockLens pair are not restored. Review the loaded frame and export again when needed; session state is not evidence that the sources remain unchanged.

### 3.2. Reopen or move a project

1. Choose **Open project (.mds)** and select the saved session.
2. Check the project folder shown on **MD Run** and confirm that its manifest and artifacts remain available.
3. Review restored paths in **Analysis** and **Load System**. Relative project references can survive a directory move, but every restored input path should be checked on the destination machine.
4. If the original project is unavailable, restore it from the archive or select the existing analysis inputs again. An old session file cannot recreate missing simulation outputs.

The application prevents destructive session switches while tracked operations are active. **New project** clears the current interface state; it does not delete completed simulation files.

## 4. Prepare a molecular system

### 4.1. Prepare the input structures

1. Inspect the biological assembly, chain composition, missing regions, alternate conformations, termini, disulfide bonds, and relevant cofactors. After choosing **Protein (PDB/GRO)** on MD Setup, **Inspect structure in 3D** opens that file in the integrated panel described in section 9.1.
2. Establish protonation states and ligand chemistry before automatic topology generation. A PDB filename does not specify the intended protonation model.
3. For a separate ligand, retain its correct bond orders, stereochemistry, formal charge, and coordinates. MOL2 or SDF generally carries more chemical information than PDB.
4. Confirm that the protein and ligand occupy the same coordinate system. MolDynStudio combines their coordinates; this step does not redock or realign the ligand.
5. Keep an untouched copy of each original input and record its source and any edits.

### 4.2. Inspect, plan, and repair a PDB structure

Use **Inspect / repair structure** on **MD Setup** before topology generation when the input needs structural review. The tool reads PDB records before selecting conformers, so alternate locations and duplicate records remain visible in the audit. It writes a separate candidate and preserves the original. GRO and mmCIF are not inputs to this dialog; retain the original deposited mmCIF and validation report alongside the PDB when available.

#### Inspect the original and map the sequence

1. Select the input under **Protein (PDB/GRO)**, then choose **Inspect / repair structure**. On **1 Inspect**, verify **Original PDB** and choose a writable **Output folder**.
2. Leave **Optional FASTA** empty to inspect the deposited PDB sequence information, or select a reference FASTA appropriate to the experimental construct. A full precursor sequence can contain a signal peptide, tag, or terminal region absent from the structure by design.
3. Choose **Inspect structure**. Read the original-file SHA-256, model and chain identities, alternate conformers, exact duplicate atom lines, close overlaps, modified residues, missing heavy atoms, and sequence findings.
4. If a FASTA was supplied, select the intended **FASTA chain** and **FASTA record**, then choose **Inspect structure** again. The dialog associates one selected FASTA record with one selected chain for that inspection. A multi-record FASTA is not automatically assigned by record order.
5. Read the sequence mapping, mismatches, ambiguity, and blocked findings before approving a gap. The audit also considers available deposited SEQRES information. Residue numbering alone is not evidence of a missing segment: numbering offsets and insertion codes can occur in a complete observed chain.

FASTA specifies residue identity, not atomic positions. If a mapping is ambiguous, select an appropriate construct-specific sequence or resolve the reference outside the application and inspect again. Do not authorize a terminal extension simply to make the structure match a longer database sequence. Sequence alignment follows the [Biopython pairwise-alignment API](https://biopython.org/docs/latest/Tutorial/chapter_pairwise.html); its result still requires biological interpretation.

#### Review a concrete repair plan

1. Open **2 Plan**. Select one **Model** if the PDB contains several, and review **Retained chains**. All chains are initially retained.
2. Review **Alternate conformers**. **Resolve alternate locations by atom completeness, then occupancy** chooses a coherent conformer for each residue, retaining shared atoms without an alternate-location label. Each residue's dropdown allows an explicit alternative to the recommendation. Record the choice used for a comparison or validation case.
3. Review **Remove exact duplicate atom records** separately from the overlap findings. A repeated identical atom record is different from two distinct atoms occupying nearby positions. The program does not automatically delete a distinct atom because of a close overlap.
4. If an erroneous atom genuinely requires deletion, enter its original PDB line ID under **Delete atom lines**, using commas or spaces, for example `120, 135`. These are file line IDs, not PDB atom serial numbers; ranges are not accepted. Check both identities and the scientific reason for deletion. Unresolved severe overlaps can block the candidate.
5. Leave **Alternative apo preparation: remove heterogens and export protein only** unchecked when retaining a complete complex. That option removes ligands, ions, and other heterogens and creates a different chemical system. It is not a routine repair of a ligand-bound structure.
6. Leave **Optional MODRES parent conversions** unchecked unless that chemical change is intentional. A MODRES parent label supports sequence interpretation; it does not imply that the modified residue should be replaced. Converting BHD to ASP, for example, removes its additional oxygen substituent.
7. Select **Build missing heavy atoms using the optional local PDBFixer backend** when the retained standard residues need heavy-atom completion. Unknown components remain fixed context; this does not reconstruct or certify their chemistry.
8. Under **Approved sequence gaps (none selected)**, select only the intervals that should be modeled. All intervals, including terminal extensions, start unchecked. Missing-heavy-atom completion and missing-residue reconstruction are separate choices. Do not select overlapping FASTA and SEQRES descriptions of the same insertion.
9. Choose **Review repair plan**. Read every proposed removal, conversion, conformer choice, and reconstruction, together with any blocking reason. Editing a choice invalidates the prior plan and candidate; review the revised plan before generating another file.

#### Generate and inspect the candidate

1. Open **3 Candidate** and choose **Generate candidate from reviewed plan**. Wait for the background operation to finish. The application prevents closing or replacing the project while this work is active.
2. Review the retained-observed and modeled-atom counts, any added residues, covalent links, **Nonstandard components retained**, and QC findings. That component list can include ligands as well as modified residues. Newly constructed coordinates are estimates. Observed coordinates are checked for preservation; reconstruction is not a global relaxation of the experimental structure.
3. Choose **Open full repair report**. Check atom identities, source line mappings, modeled-atom identities, backend versions, seed, warnings, and all blocked reasons. The short on-screen listing may omit some modeled identities; the full report contains the complete record.
4. Inspect the candidate in a molecular viewer, especially reconstructed side chains or loops, termini, active-site contacts, and retained covalent links. Finite coordinates and passing program checks do not establish that a modeled loop is physically correct.
5. Read both readiness statements. **Structural readiness: ready for review** means that the candidate passed this workflow's coordinate checks. The parameter-readiness warning identifies retained nonstandard chemistry that still requires a suitable model. The full report records these separately as `coordinate_repair_ready` and `md_requires_parameters`. Supported noncovalent ligands can proceed through the MATCH route in section 4.5; covalent adducts still require a separate validated topology. Coordinate readiness is not force-field validation.

The controlled PDBFixer step builds only approved missing residues and standard heavy atoms. It does not add hydrogens, solvent, ions, or a simulation topology. See the [PDBFixer manual](https://github.com/openmm/pdbfixer/blob/master/Manual.html) for the underlying reconstruction operations. Engine failure or failed candidate QC leaves evidence for diagnosis and prevents adoption.

Each attempt creates a new directory rather than replacing an earlier result:

```text
structure_repair_<identifier>/
  source.pdb
  source.fasta             # when supplied
  audit.json
  plan.json
  selected.pdb
  candidate.pdb
  repair_report.json
  reconstruction_<id>/     # when the modeling backend runs
    request.json
    result.json            # when the worker returns a structured result
    engine.log
```

#### Adopt the verified file

1. Open **4 Adopt** and review the candidate path, report path, SHA-256, and readiness statements.
2. Choose **Use repaired structure**. The application rechecks the candidate, report, original inputs, and recorded artifact hashes before accepting it, then records the SHA-256 of the approved report.
3. Back on **MD Setup**, confirm that **Protein (PDB/GRO)** points to the candidate and **Repair provenance** points to its report. Adoption changes the input; it does not start topology generation or MD.
4. Preserve the original PDB, optional FASTA, and repair directory at their recorded paths until preparation is complete. Editing or moving referenced inputs can invalidate verification even though copied sources remain in the repair directory. Manually changing the Protein field clears its repair-report association.
5. For supported chemistry, continue with the setup steps below. **Prepare system** verifies the adopted evidence again and records the repair provenance in the prepared project's manifest. If required parameters are absent, retain the candidate and resolve the parameterization in a separate validated workflow. Do not remove a ligand or modified residue merely to bypass this check.

Save the `.mds` session after adoption. The approved report digest persists through session saving and reopening and is checked before preparation begins. A changed report cannot be accepted merely by reopening the session. If an older repair session contains a report path without its approved digest, reopen **Inspect / repair structure**, review the candidate, and adopt it again before preparation.

#### Examples: complete 5T66 and 1ERM complexes

These examples illustrate different structural findings; they are not ready-made force-field models. Obtain the original PDB, sequence, and validation information from the official [5T66](https://www.rcsb.org/structure/5T66) and [1ERM](https://www.rcsb.org/structure/1ERM) entries. Preserve the downloaded files and their checksums. The two 5T66 protein chains belong to the deposited asymmetric unit; retaining both for this check does not establish a biological dimer.

| Case | Choices and expected interpretation |
| --- | --- |
| 5T66, both deposited protein chains with C6S | Retain both chains, both inhibitor copies, and their serine linkages. The recorded backend check selected conformer A consistently per residue and completed missing heavy atoms. No internal sequence gap was found. The expression construct starts at residue 29 [22]; residues 1–28 must not be rebuilt as a missing loop. GLN29 is an optional unobserved terminal residue and was not rebuilt in this check. The partially observed THR30 still needs heavy-atom completion. |
| 1ERM, TEM-1 with BJI and BHD214 | Retain BJI, its covalent linkage, BHD214, and BHD214's OB atom. The observed polymer sequence is complete; author numbering beginning at 26 does not justify adding residues 1–25. Leave parent conversion and apo export unchecked. The recorded backend check added no atoms or residues. |

In the recorded coordinate checks, 5T66 retained 4,404 observed atoms and added 94 heavy atoms; 1ERM retained 2,183 observed atoms and added none. Maximum observed-coordinate displacement was 0 Å in both cases. These numbers describe the specified downloaded inputs and conformer choices, not every revision or biological assembly of those entries. See the [validation record](VALIDATION_REPORT.md) for evidence scope.

The full 5T66 reference sequence can produce a terminal-gap entry covering residues 1–29. Leave that interval unselected for this complete-complex check. A separate decision to model only GLN29 would require a construct-specific sequence and a newly reviewed plan; selecting the displayed 1–29 interval would also request the excluded signal region.

Neither complete complex was taken through minimization, NVT, NPT, or production MD in this validation. Validated parameters for the boronate–serine adducts and the retained BHD residue were not available. Published boron parameterization studies provide starting literature [19–21], but their existence does not supply or validate an atom-by-atom topology for these exact retained systems. Check chemical state, connectivity, charges, atom types, bonded terms, and force-field compatibility before running them.

### 4.3. Configure MD Setup

1. Select a writable **Project folder** dedicated to this run.
2. Select the **Protein (PDB/GRO)** file. Use a structure that the selected GROMACS preparation tools can interpret correctly.
3. Leave **Ligand** empty for a protein-only system. For a separate noncovalent ligand under an AMBER-family force field, select its MOL2/SDF file. For CHARMM36m, select a reviewed MOL2 with explicit hydrogens and follow section 4.5.
4. Choose **Force Field** and a compatible **Water Model**. A force-field name in the list does not install the corresponding parameter directory. The GROMACS environment must contain it, except for the separately managed CHARMM36m package described below.
5. Set **Box Type**, **Box padding (nm)**, and **Ion concentration (M)**. Padding is a distance from the solute to the box boundary, not a box edge length.
6. For the AMBER ligand route, confirm **ACPYPE / GAFF2 (AMBER-family)**, choose **AM1-BCC** or **Gasteiger**, and set the integer **Expected net charge**. AM1-BCC is the default. These ACPYPE charge-method controls do not apply to SwissParam MATCH. RESP and user-supplied atomic charge files are not configured by this GUI. Review generated atom types, charges, and warnings before accepting a ligand topology [4, 8, 11].
7. Under **Simulation protocol**, set **Production duration (ns)**, **Temperature (K)**, and **Pressure (bar)**. Expand **Advanced protocol parameters** to set **Timestep (fs)**, **Save every (ps)**, **NVT steps**, and **NPT steps**. These controls use the same protocol generation regardless of whether the advanced group is visible.

| Field | Unit | Meaning |
| --- | --- | --- |
| Production duration | ns | Requested production trajectory length. |
| Timestep | fs | Integration step; larger values require a justified constraint/model choice. |
| Temperature | K | Thermostat target. |
| Pressure | bar | Barostat target. |
| Save every | ps | Interval for compressed coordinates and the generated energy/log output schedule. |
| NVT steps / NPT steps | integration steps | Separate equilibration-stage lengths; duration equals the step count multiplied by the timestep. |
| Box padding | nm | Solute-to-boundary padding used in box construction. |
| Ion concentration | mol/L | Requested salt concentration, in addition to neutralization behavior. |

The default values are starting parameters for a workflow, not evidence that the resulting protocol is suitable for every system. At a 2 fs timestep, 50,000 steps correspond to 100 ps. **NVT steps** and **NPT steps** each default to 50,000 and can be changed independently. Changing the timestep also changes those stages' duration. The production duration field does not set the equilibration duration.

**Short pipeline test: 2 ps per MD stage** sets a 1 fs timestep, 2,000 NVT steps, 2,000 NPT steps, and 0.002 ns production. Production output is scheduled every 0.2 ps; the NVT/NPT templates use 0.5 ps at this timestep. Minimization still precedes these stages. This preset is an execution check, not a physically equilibrated protocol or evidence of stable binding. Review and replace these short-run values before a scientific production study.

The generated templates use steepest-descent minimization, position restraints during equilibration, LINCS constraints on bonds involving hydrogen, V-rescale temperature coupling, and PME electrostatics. Restrained NPT uses isotropic C-rescale pressure coupling [27] with `refcoord-scaling = com`; unrestrained production uses isotropic Parrinello-Rahman coupling. Inspect the actual `.mdp` files before reporting these settings. The CHARMM branch uses force-switch van der Waals settings. Specialized ensembles, membranes, or restraints require an explicitly reviewed protocol.

With `refcoord-scaling = com`, GROMACS scales a single center of mass for all restrained reference coordinates, even across multiple molecules; their internal offsets remain fixed. The [GROMACS 2025.4 documentation](https://manual.gromacs.org/documentation/2025.4/user-guide/mdp-options.html#mdp-refcoord-scaling) notes that virial and pressure may be ill defined with this setting. Review the restrained geometry and use this phase for equilibration; do not draw quantitative pressure or ensemble claims from it.

### 4.4. Install CHARMM36m once

1. Select **CHARMM36m** on MD Setup.
2. Choose **Download CHARMM36m**, or obtain the official package and choose **Import package…**.
3. Wait for checksum and package validation. The supported archive name and SHA-256 value are documented in the [force-field package notes](../forcefields/README.md).
4. Confirm that the interface reports the package as ready offline.
5. Use the compatible modified TIP3P model selected by this workflow. The local package is copied into the project when required.

Download/import is an explicit installation action. Simulation preparation does not silently retrieve a different protein force field. The supported local archive is `charmm36-feb2026_cgenff-5.0.ff.tgz`. Its included residue parameters and the separate SwissParam MATCH ligand service have distinct provenance; installing the archive alone does not parameterize a ligand [7].

### 4.5. Prepare a noncovalent ligand with CHARMM36m and MATCH

This route submits a reviewed MOL2 to **SwissParam MATCH (CGenFF-derived)** and converts its returned CHARMM parameters locally with ParmEd. MATCH assigns parameters by chemical analogy [23, 24]. A successful response therefore needs chemical and force-field review; it is not an experimental validation of the ligand or its protonation state. The selected approach is MATCH, not SwissParam's separate MMFF-based method.

#### Review chemistry and choose the coordinate source

1. In **MD Setup**, select the protein or repaired complex PDB and a new **Project folder**. Select **CHARMM36m** and confirm that the official force-field package is ready offline.
2. Supply **Ligand** as one connected molecule in MOL2 format, with explicit hydrogens, unique atom names, valid elements, bond orders, and the intended protonation state. Review formal charge, tautomerism, and stereochemistry before proceeding. A filename or pH label does not establish those properties.
3. Enter **Expected net charge** for one ligand molecule. If the complex contains two copies of a dianionic ligand, enter `-2`, not `-4`; the topology separately records the molecule count.
4. For a separate ligand whose MOL2 already contains the intended bound coordinates, leave **Use all ligand poses from the protein/complex PDB** unchecked. The protein input must not also contain an unhandled duplicate of that ligand.
5. To retain every bound copy from a complex PDB, check **Use all ligand poses from the protein/complex PDB** and enter **Ligand residue name**, such as `TWB`. Each selected PDB residue must match the template's heavy-atom names and elements. Resolve alternate conformers first. The current extraction contract expects these PDB ligand copies to contain heavy atoms; the MOL2 supplies the explicit hydrogen pattern.
6. Review other compounds in the PDB. Under **Exclude extra compounds**, enter only residue names deliberately omitted from this model, separated by commas, for example `GOL, EDO`. The selected ligand, protein, and water cannot be excluded through this field. Unhandled extra compounds stop preparation instead of being silently discarded.
7. Check **I verified hydrogens, protonation and expected net charge** after completing that review. The checkbox records a user decision; the application does not calculate a physiological protonation state from pH.

For complex extraction, the original PDB and MOL2 remain unchanged. The application creates derived protein/water and ligand files, retaining each ligand copy's observed heavy-atom coordinates. Open Babel adds hydrogen coordinates under the reviewed template's named graph and protonation constraints. Graph, identity, charge, and coordinate checks reject a changed chemical model. Generated hydrogens are modeled coordinates, not crystallographic observations.

For supported CHARMM TIP3P preparation, crystal waters are separated while `pdb2gmx` processes the protein, then included in the assembled coordinates and topology. Observed water oxygens are retained. A neutral oxygen-only water receives two modeled hydrogens; a complete, valid water retains its observed hydrogen coordinates. Review `water_provenance.json` and the manifest's `crystal_waters` entry. Hydrogen orientations require minimization, and standard GRO output rounds positions to 0.001 nm. Charged, partly hydrogenated, unresolved, or explicitly linked waters require review rather than automatic treatment as ordinary TIP3P.

#### Authorize parameterization or reuse verified results

1. Read the linked [SwissParam service and terms](https://www.swissparam.ch/). If new parameters are needed, check **Allow uploading this ligand MOL2 to SwissParam**. This sends the ligand molecule to the public service; it does not upload the protein PDB.
2. If a matching verified cache already exists, leave upload consent unchecked. Cached files are checked against the exact input digest, method, endpoint, archive, and output hashes before reuse. A changed MOL2, including its coordinates or atom names, can require a new cache entry even when the compound name is unchanged.
3. Complete the simulation settings and choose **Prepare system**. Watch the log for queued/running status, retrieval, chemical checks, conversion, and system assembly. A submitted session number is not a completed parameterization.
4. If the service times out, preserve the saved session evidence. Retrying with the same input and required consent can resume that session. A corrupted cache, unexpected response, failed calculation, or changed chemical identity stops the workflow.
5. Reconfirm chemistry and upload choices after changing ligand-related inputs or reopening a project. These checkboxes are cleared deliberately; a saved session does not authorize a new upload.

The service must preserve the requested molecule, not merely produce parameter files. Check atom names and elements, hydrogen count and attachment, bond graph and bond orders, and the returned topology's total charge. MolDynStudio rejects a charge difference beyond its numerical tolerance rather than silently changing the requested integer charge. Small printed-charge rounding is retained and recorded; it is not an instruction to redistribute atomic charges manually.

#### Review conversion and assembly evidence

1. Inspect the returned MOL2, RTF, parameter files, and MATCH log alongside the submitted MOL2. Retain the service session and provenance record for reproducibility.
2. Review the local ligand topology, coordinate file, parameter include, and reference PSF. ParmEd performs parameter matching and conversion of the supported potential terms [25]. The adapter rejects unsupported CHARMM directives instead of dropping them silently; this includes arbitrary patches, external-residue references, CMAP, NBFIX, and polarizable terms.
3. For a complex PDB, inspect `complex_input_provenance.json` in the derived `complex_inputs` directory. Confirm selected residue identities, ligand-copy count, explicit exclusions, source hashes, atom mapping, and heavy-coordinate preservation.
4. Inspect the `ligand_parameterization` and, when present, `complex_inputs` records in `moldynstudio_run.json`. Confirm that the final topology includes the expected number of ligand molecules, compatible modified TIP3P water, and the correct ion composition.
5. Review the preparation log and final coordinates before **Run All**. For a new chemical class, compare equivalent single-configuration energies and force-field terms across the reference and converted representations before interpreting production simulations. A file-format conversion or short successful trajectory does not establish parameter accuracy.

The [ParmEd project](https://github.com/ParmEd/ParmEd) requests reference [25] when citing its use. Retain the actual ParmEd version, MATCH response, force-field archive version, and generated includes; the method names alone are not sufficient to reproduce a converted model.

The ligand atom types receive unique names before combination with the protein topology. Cross interactions use CHARMM/Lorentz–Berthelot mixing; the adapter does not infer missing intermolecular NBFIX corrections. Preserving the supplied MATCH potential does not make the result equivalent to a fresh CGenFF 5.0 assignment by the licensed CGenFF server. For charged groups such as phosphonates, protein/ion cross interactions, including sodium interactions, need scientific validation beyond an execution test before quantitative binding claims are made.

#### Worked setup: 6D15 with both TWB copies

The official [6D15 entry](https://www.rcsb.org/structure/6D15) contains KPC-2 with two noncovalent TWB molecules. The deposited construct has 290 sequence residues and 270 observed protein residues. In the audited input, selecting conformer B for LYS111, GLN191, ARG266, and GLU288 leaves 2,016 protein heavy atoms, two 18-heavy-atom TWB copies, six glycerol heavy atoms, and 269 waters. No internal sequence segment or missing standard heavy atom was reconstructed. Author-number gaps are not treated as missing residues. The [validation record](VALIDATION_REPORT.md#charmmmatch-and-6d15-addendum--9-october-2026) summarizes the input checks and observed results. Raw local validation files are not included in the public source distribution.

1. Inspect and adopt the reviewed 6D15 candidate. Keep the observed terminal/tag residues and deposited disulfide; leave unobserved terminal intervals unselected.
2. Select **CHARMM36m** and the reviewed `TWB_A301_minus2_named.mol2` chemical template. This template represents C12H11O5P with 18 heavy atoms, 11 hydrogens, and 30 bonds.
3. Enter **Expected net charge** as `-2`, check **Use all ligand poses from the protein/complex PDB**, and enter `TWB` under **Ligand residue name**. Both A301 and A302 are then requested using their own bound heavy-atom coordinates. Their crystallographic occupancies do not establish physiological binding stoichiometry.
4. Enter `GOL` under **Exclude extra compounds** only for the reviewed glycerol-free simulation model. This is an explicit modeling change; the original deposited structure and repaired candidate still retain glycerol. Keep both TWB copies and the waters.
5. Review the hydrogen pattern and net charge, then choose the appropriate upload/cache option. The accepted MOL2-based response preserved the molecule and returned an RTF charge sum of −2.000010, reflecting service rounding. An earlier SMILES-based response changed the requested protonation and was not accepted.
6. For an initial execution check, select **Short pipeline test: 2 ps per MD stage**, prepare the system, inspect its evidence, and then run the four stages. Continue to Analysis only when actual matching production outputs exist. Check the [validation record](VALIDATION_REPORT.md) for which calculations have been completed on this case.
7. Follow section 6.1 to prepare and verify a separate whole/centered trajectory. Load that trajectory with the original matching production TPR. Use `protein` for the standard protein analyses and `protein and name CA` for a compact PCA calculation; the hydrogen-bond partner is `resname LIG` in this prepared system.
8. Open **Trajectory frames**, review the frame and periodic imaging, and export each ligand copy separately if the question concerns its own contacts. In the recorded TPR, `resname LIG and resid 271` and `resname LIG and resid 272` identify the two complete copies. Confirm identifiers in your own prepared topology before reusing these selections. Follow section 9 to choose DockLens and open an exported pair.
9. Retain the analysis manifests, paired-frame provenance, logs, and parameterization evidence. Save the session and export an evidence bundle using section 13; archive the original and processed trajectory files separately.

The recorded 6D15 execution completed fresh preparation, minimization, 2 ps NVT, 2 ps NPT, and 2 ps production using GROMACS 2025.4. Minimization reached the requested maximum-force tolerance after 1,028 steps. This verifies the short execution path with both ligand copies; it does not establish physical equilibration, adequate sampling, or binding affinity.

Use the residue names in the prepared topology for subsequent selections. In this case, the prepared TPR names both 29-atom TWB copies `LIG`, so `resname LIG` selects both. The deposited name `TWB` remains the input-extraction choice. For analysis or DockLens export of one copy, inspect the prepared residue identifiers and restrict the selection accordingly; do not assume deposited residue numbers survive topology generation.

The dianionic TWB state is a model selected for a pH 7.4 simulation hypothesis, supported by a microspecies prediction; it is not a measured bound-state protonation assignment. Pemberton et al. report KPC-2 inhibition assays at pH 7.0, while the deposited 6D15 record does not establish the crystal pH [26]. Neither assay pH nor the neutral chemical-component dictionary entry alone determines the simulation state. Evaluate alternative plausible states when that uncertainty affects the scientific question.

This noncovalent workflow does not enable the covalent C6S/BJI adducts in 5T66 and 1ERM. Their separate parameterization requirements described in section 4.2 remain in force.

### 4.6. Inspect MDP files and prepare the project

1. Read the **MDP Preview**. Use **Preview production MDP** to open an editable copy of the production input.
2. Use **Save .MDP Files** to write the generated `em.mdp`, `nvt.mdp`, `npt.mdp`, and `md.mdp` files when needed. Saving an MDP file alone does not create a prepared system.
3. Choose **Prepare system** on MD Setup. It runs structure validation, topology generation, ligand preparation when applicable, box construction, solvation, ion addition, and MDP generation.
4. Watch the log until preparation succeeds or reports a specific failure. An interface preview is not a successful preparation result.

6. Choose **Review MD run** to open **MD Run** and its prepared-input review. Successful preparation supplies the project and manifest; review and execution remain separate actions. Save the `.mds` session.

Regenerating MDP files writes generated settings again. If a reviewed manual modification is required, make it after generation, retain the final file, and avoid regenerating it before execution. The MDP editor saves a file; it does not update every GUI parameter from edited text.

The temporary `ions.mdp` uses cut-off electrostatics only to create the TPR consumed by `genion`. That TPR is not executed as a simulation. Minimization, NVT, NPT, and production keep their generated PME electrostatics settings; do not copy the ion-placement preprocessing settings into an MD protocol.

## 5. Run, monitor, stop, and resume MD

### 5.1. Execute the four stages

1. Open **MD Run**, or choose **Review MD run** from MD Setup. Check the displayed prepared project and **Prepared run review**.
2. Choose **Review run / MDP files** and inspect the summary and actual `em.mdp`, `nvt.mdp`, `npt.mdp`, and `md.mdp` text. Use **Check environment** to check the recorded executable and resources as described below.
3. Choose **Run All**. The required order is minimization, NVT equilibration, NPT equilibration, then production MD.
4. Observe each stage status and **Terminal Output**. Progress and plots are populated from real GROMACS output; an empty plot means that no corresponding numeric record has yet been parsed.
5. Inspect temperature, pressure, and energy trends along with the GROMACS log and stage QC messages.
6. At completion, verify the production files. The application transfers available production topology, trajectory, and energy paths to the analysis workflow without automatically running analyses. If the 3D panel exists, its source fields receive the production paths without opening a reader. Choose **Load 3D view** to inspect them; **Open Trajectory Viewer** on Analysis also opens the same panel with the current Analysis inputs.

Typical project files are:

```text
project/
  moldynstudio_run.json
  system.gro
  topol.top
  em.mdp  nvt.mdp  npt.mdp  md.mdp
  em.*    nvt.*    npt.*    md.*
  ligand/                 # separate ligand workflow, when present
```

The manifest records pipeline state and available execution evidence. Stage prefixes identify the corresponding `.tpr`, coordinate, log, energy, trajectory, and checkpoint files. Not every extension is produced at every stage.

**Clear Log** clears the visible terminal panel. Preserve the actual GROMACS log files for diagnosis and reporting. **Copy Last Line** copies only the final visible line, which rarely contains enough context to diagnose a failed calculation.

#### Prepared inputs and pending setup changes

Successful preparation records the submitted system and protocol choices in the manifest's `preparation_review`, including a `setup_snapshot`. MD Run compares that snapshot with the current MD Setup draft. Changing a recorded choice, such as the input path, force field, box, salt concentration, ligand charge, or protocol length, displays **Pending MD Setup changes** and disables **Run All** and **Resume**. Return to **MD Setup** and either restore the prepared values or prepare again with the intended changes. Editing the draft alone leaves the previous prepared files and results available for inspection; preparing again can regenerate files, so use a separate project folder when retaining an independent run.

An older manifest without the snapshot reports **Setup comparison not recorded in this older project**. Missing preparation details appear as **Not recorded** in the review. Existing MDPs remain reviewable, but the application cannot establish that an unrecorded setup matches the current draft. Existing artifact and restart checks still apply.

The review's **Prepared run** tab combines recorded system, force-field, water, ligand, and execution settings with stage durations and production settings read from the four on-disk MDPs. Missing or unreadable MDPs produce review notes. The dialog is read-only and does not regenerate inputs or launch MD. The setup comparison checks recorded choices, not every manual edit to a file; inspect the actual MDP tabs before executing or reporting a modified protocol. A protocol with 2 ps each for NVT, NPT, and production is explicitly labeled a short execution test, with no equilibration claim.

#### Check the selected execution environment

**Check environment** runs the GROMACS capability probe in a background thread. The panel identifies **Windows → WSL Linux** or **Linux native**, the recorded GROMACS executable, requested CPU threads, and GPU mode. It reports the selected build's version, compiled GPU backend, and resource arguments; a reported GPU backend does not demonstrate usable hardware or actual GPU use. Inspect the `mdrun` log for the resources used during execution. A previous check is reset when the recorded project or execution context changes.

If the check fails, use **Settings** to inspect the executable and Conda environment. If a run fails, the panel retains the failure message and points to **MD Setup** for input problems, **Settings** for execution resources, and **Open project / logs** for the project folder and stage logs. Preserve the first concrete error and preceding log context before retrying. An environment check is an execution diagnostic, not validation of the molecular model.

### 5.2. Stop and recover

1. Choose **Stop** to request cancellation of the active pipeline.
2. Wait until the external process and worker have stopped. Do not assume that closing a window created a usable checkpoint.
3. Preserve the project folder unchanged. Check the saved stage status and available artifacts.
4. Select an enabled restart point and choose **Resume**. A stage restart reruns the selected stage using validated prerequisite outputs.
5. For interrupted production with a valid checkpoint, choose **Resume Production checkpoint** in the resume selector and then **Resume**. This continues the existing production run with GROMACS `-cpi`.

Checkpoint continuation requires the existing `md.cpt`, `md.tpr`, `md.log`, `md.edr`, and associated output continuity. Do not truncate, rename, replace, or partly restore production files between interruption and continuation. A fresh production stage and checkpoint continuation are different operations; retain the intended protocol and log evidence for the one used.

TPR and checkpoint validation uses the GROMACS executable and Conda environment recorded in the run manifest. On Windows, file paths are translated for that WSL backend. If validation reports an unavailable executable or unreadable file, check the recorded environment and its access to the project before resuming; a different `gmx` on the host PATH is not a substitute for that recorded configuration.

### 5.3. Read stage QC correctly

A successful process exit and nonempty outputs are necessary execution checks. Stage QC can also flag missing or implausible numeric records. Neither establishes that the system reached equilibrium or that its physical model is appropriate. Inspect structural behavior, thermostat/barostat behavior, restraint release, and replicate agreement before choosing the production interval for scientific analysis [12, 13].

Minimization has separate QC rules. A potential-energy decrease is expected, so its total change is recorded without applying an MD energy-drift criterion. The checks inspect numeric finiteness and read the final maximum force, requested tolerance, and step count when the GROMACS log provides them. Force-tolerance convergence is reported only when the log states it explicitly. Temperature, density, and pressure equilibrium criteria do not apply to minimization. For dynamics stages, inspect the appropriate time-series checks and their limitations.

## 6. Load an existing trajectory

1. Open **Load System**.
2. Select the matching **TPR file** and **Trajectory**. Select **Energy file** if energy-derived QC will be generated.
3. Record an index file, reference structure, or ligand residue name if useful for the session. These fields are not a promise that every downstream analysis consumes them; inspect its own controls and metadata.
4. Choose **Validate and use inputs**. This checks the required paths and forwards topology, trajectory, and energy to Analysis. Format and atom compatibility are checked when the backend reads them.
5. Open **Analysis** and review the transferred paths.

Alternatively, select inputs directly on Analysis. A coordinate file or TPR can supply topology information to supported readers; a GROMACS text `.top` file alone is not a complete coordinate-bearing trajectory topology. Removing solvent or selecting atoms in a trajectory changes its atom count. Use the matching reduced topology and keep atom order unchanged.

Before interpreting shape, RMSD, RMSF, PCA, SASA, or frame contacts, ensure that molecules are whole and periodic-image handling is appropriate. The configuration page named **Trajectory Preprocessing** does not execute those transformations. Use a validated external GROMACS/CPPTRAJ procedure, retain its commands, and reload the resulting matching files. Fitting removes overall translation/rotation; it does not repair broken molecules.

### 6.1. Prepare a separate trajectory for analysis

A molecule can appear split across the periodic box in a raw XTC even when its bonds have normal minimum-image distances. That representation alone is not an MD failure. It must nevertheless be corrected before analyses that use ordinary Cartesian coordinates or before exporting a receptor–ligand frame.

1. Preserve the original `md.tpr` and `md.xtc`. Choose a new output directory and retain the transformation commands and log.
2. On Windows, open the configured WSL distribution's terminal. Change to the project's Linux path, for example `/mnt/c/MD/study/rep01`. On Linux, open a terminal in the project directory. Use the Conda environment and GROMACS executable recorded for this run. In the commands below, replace `moldynstudio` and `gmx` if those recorded values differ.
3. For the solvated protein–ligand case, create a derived trajectory with this GROMACS procedure:

   ```bash
   set -o pipefail
   mkdir -p analysis_inputs
   conda run --no-capture-output -n moldynstudio gmx trjconv -s md.tpr -f md.xtc -o analysis_inputs/md_centered.xtc -pbc mol -center 2>&1 | tee analysis_inputs/trjconv.log
   ```

4. At the prompts, select **Protein** for centering and **System** for output. Read the displayed group names; numeric group IDs can differ between projects. Outputting the complete system preserves atom count and order for the original TPR. The original files remain unchanged.
5. Check that the command finished successfully and inspect the derived trajectory. Confirm that each intended molecule is whole and the receptor and selected ligand occupy the same periodic image. Check multiple frames, including the first and last. If this fails for a multichain assembly or a moving ligand, establish the appropriate complex-specific transformation before proceeding; centering alone is not proof of correct image assignment. The [GROMACS trjconv documentation](https://manual.gromacs.org/documentation/2025.4/onlinehelp/gmx-trjconv.html) describes the available periodic-boundary operations.
6. Check file readability and retain input/output hashes:

   ```bash
   conda run --no-capture-output -n moldynstudio gmx check -f analysis_inputs/md_centered.xtc
   sha256sum md.tpr md.xtc analysis_inputs/md_centered.xtc > analysis_inputs/SHA256SUMS.txt
   ```

7. In **Analysis**, select the original matching `md.tpr` and the derived `analysis_inputs/md_centered.xtc`. Confirm **Molecules are whole and PBC artifacts have been corrected** only after the coordinate review. Use this same verified pair in **Trajectory frames** for DockLens export.

File readability does not establish correct periodic imaging. Keep the trajectory's untransformed source, processing history, and hashes alongside results. MolDynStudio's preprocessing preview does not run these terminal commands or independently certify their output.

## 7. Run trajectory analyses

Python analyses use MDAnalysis and MDTraj [2, 3]. Exported CSV tables normalize time to ns and lengths to nm. SASA is reported in nm², angles in degrees, and contact frequency as a fraction. Source/backend metadata can retain native units: for example, PCA variance is recorded in angstrom squared. One nanometre equals 10 angstroms; one square nanometre equals 100 square angstroms. Read the named columns and metadata before combining outputs.

### 7.1. Shared procedure

1. Open **Analysis > Analysis Tools** and select the matching topology and trajectory.
2. Set **Output folder**. Each run writes a fresh `analysis_<identifier>` child directory rather than overwriting a previous result set.
3. Enter **Atom selection (MDAnalysis)**. The default `protein` selects recognized protein atoms. Examples include `backbone`, `protein and name CA`, and `protein and resid 10:50`; verify that the selection represents the intended atoms in this topology.
4. For hydrogen bonds, set **H-bond partner selection**, initially `resname LIG`. The primary selection and partner define the groups being compared. A ligand name must match the actual topology.
5. Inspect the trajectory and select **Molecules are whole and PBC artifacts have been corrected** after the required preparation. This confirmation records the review; it does not perform or verify periodic-boundary correction.
6. Select the analyses to execute and choose **Run selected analyses**. Use different runs when analyses require different selections; a C-alpha-only selection appropriate for PCA cannot supply the complete backbone required for DSSP or Ramachandran analysis.
7. Read the results log. Each analysis has its own success/failure record. A failure in one calculation can coexist with valid outputs from independent selected calculations.
8. Open the output directory and inspect its CSV files and `analysis_manifest.json`. The manifest records selections, source and output hashes, package versions, timing, atom/residue mappings where applicable, and errors.
9. Inspect the automatically forwarded RMSD, RMSF, radius-of-gyration, and SASA outputs in **Results Viewer > QC Dashboard**. Other suitable CSV files can be imported manually, or plotted externally. Inspect CSV column names first. DSSP, hydrogen-bond events, contact frequencies, and dihedral tables do not have the same layout as a single time series.

To cancel a batch, choose **Stop after current analysis**. The active calculation finishes before remaining selections are skipped, and the manifest records cancellation. This control does not immediately terminate a library call already in progress.

The current selection workflow uses the supplied trajectory. It does not apply the time-window presets from preview-only pages. To analyze an equilibrated interval or a subset of stored frames, create a documented matching trajectory segment externally and select that file here.

### 7.2. RMSD

Select **RMSD**, choose the atoms whose structural deviation should be measured, and run the analysis. The selected atoms are fitted by a rigid-body least-squares procedure to their coordinates in trajectory frame 0. Inspect `rmsd.csv`, including the time, RMSD in nm, and source frame columns.

This calculation fits and measures the same selected group. A ligand-only selection therefore measures ligand internal conformational change after ligand fitting; it does not measure ligand displacement relative to a fitted receptor. Keep the selection and reference convention constant when comparing trajectories.

### 7.3. RMSF

Select **RMSF** and enter a justified selection. For one value per C-alpha atom, use `protein and name CA`. The selected group must contain at least three atoms for alignment. Run the calculation and inspect `rmsf.csv` together with the atom mapping in the manifest.

RMSF is calculated after fitting selected atoms to frame 0. Each output value belongs to an atom. Selecting all protein atoms produces multiple values for a residue; the software does not average them into a residue RMSF. Report both the fitting selection and the measured selection, which are the same in this workflow.

### 7.4. Radius of gyration

Select **Radius of gyration**, choose a complete molecule or other intended group, and run the calculation. Inspect `radius_of_gyration.csv`. The reported value is mass-weighted and expressed in nm. Reliable masses and whole molecules are required; apparent expansion caused by a molecule split across a periodic boundary should be corrected before interpretation.

### 7.5. SASA

Select **SASA** and choose complete residues or the intended molecular surface. Run the calculation and inspect `sasa.csv`. The current MDTraj calculation uses the Shrake-Rupley algorithm with a 0.14 nm probe radius and 960 sphere points per atom, then sums atom areas to report total area in nm² [3, 15].

Only selected atoms are retained for this calculation. Selecting the protein alone estimates its surface after unselected ligand/solvent atoms have been removed; this is not automatically a binding-interface burial measurement. Report the selection and calculate any complex/receptor/ligand area differences under a consistent protocol.

### 7.6. Hydrogen bonds

Select **Hydrogen bonds**, set the primary selection and **H-bond partner selection**, and provide a topology with the required bonds, charges, and explicit hydrogens. A matching TPR is preferable to a coordinate-only PDB. Run the calculation and inspect `hydrogen_bonds.csv`.

Rows describe individual detected bonds with the source frame, original zero-based donor/hydrogen/acceptor atom indices, donor-acceptor distance in nm, and angle in degrees. The current geometric criteria are donor-acceptor distance at most 0.30 nm and donor-hydrogen-acceptor angle above 150°. A header-only result can indicate that no bonds satisfied the criteria. This table is not automatically reduced to counts or occupancies. Chemical donor/acceptor assignment is not replaced by a generic atom-name guess when topology information is missing.

### 7.7. PCA

Select **PCA**, choose a manageable atom set such as `protein and name CA`, and run the calculation. At least three selected atoms and four frames are needed for the default three-component result. The selected coordinates are fitted to frame 0 before both covariance estimation and projection.

Inspect `pca.csv` for the three projections in nm and the manifest for variance/cumulative-variance metadata. Variance metadata retains angstrom-squared units. The implementation rejects covariance matrices larger than 512 MiB; reducing the atom selection changes the scientific observable and should be documented. Components estimated independently for two trajectories can have different directions and signs, so their numeric projections are not automatically comparable.

### 7.8. DSSP

Select **DSSP**, retain complete protein residues, and run the calculation. Inspect `dssp.csv` for assignments by frame and residue. Simplified assignments are `H` for helix, `E` for extended strand, and `C` for coil; `NA` denotes an unavailable assignment. The computation uses MDTraj's implementation of DSSP [3, 16]. Do not interpret missing assignments as coil or use a C-alpha-only topology for backbone secondary-structure assignment.

### 7.9. Contact map

Select **Contact map**, retain the intended complete protein residues, and run the calculation. Inspect `contact_map.csv` and its residue mapping. The current definition uses the closest heavy-atom distance, a 0.45 nm threshold, and residue pairs separated by at least three positions in the selected topology. Immediate and next-nearest sequence neighbors are excluded.

The reported frequency is the fraction of supplied frames below the cutoff for each pair. It does not include an uncertainty estimate and is not a binding probability. Unlike the single-frame DockLens export, this analysis does aggregate its defined pair contacts over the supplied trajectory.

### 7.10. Ramachandran analysis

Select **Ramachandran**, choose complete protein residues, and run the calculation. Inspect `ramachandran.csv` for phi/psi values in degrees, paired by residue identity and source frame. Terminal or incomplete residues can lack one torsion and therefore lack a paired result. Use an appropriate reference distribution for residue type if conformational outliers will be classified; the exported angles alone are not a stereochemical validation report.

## 8. Generate and interpret QC results

### 8.1. Generate GROMACS QC data

1. In **Analysis**, select a matching topology and trajectory. A production TPR is the preferred GROMACS input.
2. Set the **Output folder**. QC execution writes a fresh `qc_<identifier>` directory beneath this root, so successive runs can be distinguished.
3. Supply the original `.edr` file if temperature, pressure, density, and energy terms are required. XVG/CSV files are already extracted data and should be imported into the dashboard instead of being treated as binary energy files.
4. Set **GROMACS QC group**, initially `Protein`, to an existing compatible GROMACS group. Review periodic-boundary preparation and confirm **Molecules are whole and PBC artifacts have been corrected**.
5. Choose **Preview QC Commands** and inspect the commands. This operation does not execute them. Choose **Generate QC Dashboard** to execute, then read the log and wait for successful completion.
6. Inspect the generated XVG files, execution metadata, and the **Results Viewer > QC Dashboard** display. The QC commands use the GROMACS executable and Conda environment configured in Preferences.

The pipeline extracts RMSD, radius of gyration, SASA, and residue RMSF for the chosen group, plus available requested energy-derived quantities when an EDR is supplied. These calculations use GROMACS group names. A Python atom-selection expression is a different syntax and should not be entered as a GROMACS group name.

An energy file may lack an ensemble-dependent term, such as density for a constant-volume run. When GROMACS explicitly reports that a requested term is absent, the pipeline retains valid outputs, displays **Partial energy coverage**, and records the missing term and reason in `qc_commands.json`. Other command failures remain failures; they are not treated as missing measurements.

### 8.2. Import previously generated data

1. Open **Results Viewer > QC Dashboard**.
2. Choose **Add XVG/CSV Files** and select numeric XVG, CSV, DAT, or TXT files.
3. Use descriptive filenames, such as `rmsd_rep01.xvg` and `rmsd_rep02.xvg`, because metric and replicate labels are inferred from filenames.
4. Inspect any skipped-file messages and the point counts. The importer uses the first coordinate column and first value column; a multicolumn file is not automatically expanded into one series per column.
5. Use the metric selector to choose the displayed time-series observable. Residue profiles are plotted separately from time series, and incompatible units are not combined into the same comparison.
6. Use **Clear** before switching to an unrelated dataset. Reloading the same source path replaces that source's data rather than creating a second independent replicate.

Preserve XVG axis labels. Recognized time units can be normalized to ns; `time_ns` in a CSV header identifies an ns axis. A missing unit remains unknown. RMSF is a distribution along atoms/residues, not a time series, and its horizontal coordinate must not be interpreted as time.

### 8.3. Interpret the dashboard

The table reports point count, final-window mean and standard deviation, drift, slope, a heuristic burn-in estimate where applicable, and a status message. The final window is the final 40% of points for ordinary time series. Read the status explanation as well as its color or short label.

- **FAIL** indicates a failed numeric or input check; inspect the source data before further interpretation.
- **WARN** identifies a condition requiring review, including limited replicate evidence or unstable behavior.
- **OK** means that the implemented numeric checks did not flag the series. It is not a convergence certificate.

A recommended analysis start is a heuristic suggestion, and may remain undetermined when units or evidence are insufficient. The GUI does not automatically discard trajectory frames or rewrite the production interval based on this suggestion. Apply a scientifically justified interval explicitly in the analysis protocol.

Replicate comparison uses summaries of loaded series. Import independent replicates with the same observable, atom selection, preprocessing, units, and comparable sampling windows. A small spread between final means does not establish independent sampling, nor does a flat RMSD establish adequate sampling of all relevant conformations. Report uncertainty using a method that considers time correlation and sampling quality [13].

### 8.4. Inspect a measured point in 3D

1. Run the required analyses from **Analysis** using the matching topology, trajectory, and reviewed preprocessing. Completed RMSD, RMSF, radius-of-gyration, and SASA outputs are offered to **Results Viewer > QC Dashboard**. Keep each generated CSV together with its adjacent `analysis_manifest.json` and the original referenced inputs. Previously generated outputs can also be added through **Add XVG/CSV Files**.
2. Choose the source file in **Measured Series**; its full path appears in the selector's tooltip. Selecting a row in the summary table also selects that series. **Plot** retains the measured curve; **Measured points** lists source rows in their original order, beginning at **Row (0-based)** `0`. Verified CSV columns retain their explicit units and frame or atom indices.
3. Click one plotted point, double-click a measured row, or select a row and activate **Show selected point in 3D**. A selected point is marked on the plot. When points or different series overlap, choose the exact source file and row in **Measured points**; the application does not guess which overlapping observation was intended.
4. For a time-series CSV, the shared 3D panel opens the sources recorded by that analysis, reads the exact stored `frame` index, and checks the reader's time against `time_ns` converted to ps. It does not estimate a frame from the spacing between points. Read the panel status for the source filename, zero-based row, exact frame, and reader time.
5. For RMSF, the source `atom_index` and topology metadata identify the measured atom and its unique residue/segment. The complete source residue is highlighted in pink with a white outline at the current frame. The highlight is drawn above the molecular context for visibility; it does not represent physical occlusion or a new selection. The status identifies the source atom and residue. RMSF remains the existing aligned, per-atom measurement: highlighting a residue does not average its atoms or calculate a residue RMSF.
6. Wait for source verification and frame reading to finish before selecting another point. A request during another operation reports **Point not opened**; select it again when idle. Invalid or changed data produce an explicit failure. Normal frame navigation clears the residue overlay, and a new/opened session clears the previous dashboard context.

The output hash, columns, row count, source paths, and topology/trajectory hashes must match the manifest. The first source-hash check runs in the existing background frame worker; subsequent checks reuse verified hashes only while source signatures remain unchanged. If a result changes after plotting, add it again to refresh the displayed rows; regenerate analysis when its source inputs changed. Absolute source paths must be valid on the current operating system. Moving files does not automatically remap provenance.

Imported XVG or CSV files without the required completed analysis result and manifest remain readable in the dashboard. The status explains why their 3D link is unavailable; no trajectory is silently assigned from the currently open project. Generate a new result through **Analysis** when a verified link is needed.

The highlight leaves **Receptor selection** and **Ligand selection** unchanged for the same source pair. Opening a different analysis source pair initializes the usual `protein` and `resname LIG` selections. Export still uses only the applied receptor/ligand groups from the displayed frame, with the existing periodic-boundary review and source checks. A visual highlight alone does not authorize export or establish interactions, affinity, or convergence.

## 9. Inspect a frame and open it in DockLens

The integrated panel inspects a structure or reads a trajectory one frame at a time from disk. Its paired-frame workflow exports a receptor and ligand from one observed trajectory frame. It does not redock the ligand, estimate binding affinity, or calculate trajectory-wide interaction occupancy. MDAnalysis provides reading and atom selections [2]; the native display uses the application's existing Matplotlib and Qt dependencies.

### 9.1. Open and navigate the integrated 3D view

1. Choose **View > 3D structures and trajectories**. The panel initially docks below the workflow; use its title bar to float it or dock it at the right. **MD Setup > Inspect structure in 3D** loads the selected protein file. **Analysis > Open Trajectory Viewer** loads the current Analysis sources into this same panel.
2. Check **Structure / topology (PDB, GRO, TPR)**. For structure-only inspection, leave **Trajectory (optional for a structure)** empty and choose **Load 3D view**. A readable source supplies one coordinate frame, with `all` as the initial receptor selection and an empty ligand selection. No simulation time is assigned, playback is unavailable, and molecular-dynamics frame export is disabled. A compatible TPR reader is still required.
3. For a trajectory, choose its matching topology and trajectory, then **Load 3D view**. Atom count, order, and identities must agree. A missing file, unsupported reader format, or invalid selection produces an explicit failure in the panel status; correct the inputs and load again. **Reload trajectory** reopens the displayed sources.
4. Use **Previous**, **Next**, the frame slider, or **Frame index (0-based)** to navigate. Index `0` is the first stored frame. **Play** advances frames until the end; **Pause** stops playback, and hiding the panel also pauses it. Time is the reader's value in ps, or unavailable when the reader provides no finite time. Verify the source timestep and time origin; an index is not a time in ns.
5. Rotate the native view with the mouse. Its coordinates are in angstroms. The camera orientation and axis limits remain stable between frames; **Reset view** refits the current coordinates. Selected receptor atoms are blue and ligand atoms orange. Bonds are drawn only when supplied by the source topology and both endpoints are displayed. Missing connectivity is not inferred, so absent lines do not establish absent chemical bonds.
6. Set **Receptor selection** and **Ligand selection**, then choose **Show frame** to apply edits. Trajectories initially use `protein` and `resname LIG`. Replace `LIG` with the prepared residue name; select one complete ligand copy for a paired export. Receptor and ligand selections must not overlap.

| Selection example | Meaning when those source identities are available |
| --- | --- |
| `all` | Every atom in the source. |
| `protein and chainID A` | Protein atoms assigned to chain A. |
| `protein and resid 10:20` | Protein atoms in the inclusive residue-number interval. |
| `resname LIG` | Every residue named LIG. |
| `resname LIG and resid 271` | The LIG copy with that prepared residue number. |

The panel samples large selections to about 6,000 displayed atoms to limit drawing cost. Its counts describe the full selected groups, and export retains every selected atom subject to PDB validation. This display reduction does not rewrite the source or create a reduced trajectory. Coordinates are shown without automatic fitting, centering, wrapping, or periodic-boundary correction.

Windows XTC/TRR readers use a matching ASCII short-path alias when the selected path contains non-ASCII characters. The original source paths remain in provenance. If the filesystem does not provide that alias, choose files under ASCII-only folder and file names; the viewer reports this explicitly and does not copy large trajectories automatically.

Pause playback and wait for frame loading or export before starting another project operation or switching sessions. The application tracks viewer work in its busy and close guards. Before preparation or MD execution, it closes the idle reader to release source handles, including Windows file locks; reload the view after the operation finishes. This releases a reader without deleting or changing the original files.

The dock's close button hides it and pauses playback while retaining the loaded context. Source handles are released when sources change, before project writes, when starting/opening another session, or when closing MolDynStudio. A read failure invalidates cached exports and periodic-image consent; a successful Show/Reload is required before a new export.

### 9.2. Export the current trajectory frame to DockLens

1. Load a matching topology and explicit trajectory using section 9.1, then pause on the intended frame. A standalone structure is inspectable but is not exported as molecular-dynamics evidence.
2. Apply the intended selections with **Show frame**. Confirm that both groups are nonempty and disjoint and that the ligand selection includes the complete molecule. A protein-only trajectory can be inspected, but paired DockLens export requires a ligand.
3. Choose the DockLens scientific profile (**PLIP**, **LUNA**, **DSV**, or **LUNA×DSV**) and an output folder. Retain the same profile when making comparisons.
4. Inspect periodic boundaries. Keep the receptor and ligand in the same physical image using a documented preprocessing procedure. Select **I have reviewed periodic boundaries and kept the receptor and ligand in the same image.** only after this review. Changing the frame, selections, sources, or scientific profile invalidates the earlier export and requires a fresh confirmation.
5. Choose **Export current frame**, then inspect the new `frame_<index>_<identifier>` directory. It contains `receptor.pdb`, `ligand.pdb`, `provenance.json`, `docklens_launch.json`, and `reports/`. The provenance records the selected frame, reader time in ps, source hashes, selections, and atom/residue mappings. The launch manifest requests the output `reports/docklens_result_frame.json`.
6. Select the installed **DockLens executable** and choose **Open exported frame in DockLens**. The launcher passes the generated manifest to DockLens through its `--manifest` option.
7. In DockLens, select **Molecular dynamics frames** as the evidence context before interpreting the frame. The launch manifest does not set this interpretation mode automatically.
8. Save the DockLens outputs with the exported frame and retain the provenance file. MolDynStudio does not automatically import the returned DockLens result.

If launch fails, verify that the selected executable is a compatible DockLens application and supports `--manifest`. The exported files remain available for manual import. DockLens installation and its scientific dependencies are separate from MolDynStudio.

The profile labels identify DockLens criteria. Its PLIP profile retains legacy cutoffs, and its LUNA/DSV profiles apply their documented parameters through DockLens' own feature perception. They do not launch the original PLIP, LUNA, or Discovery Studio engines, and identical outputs are not implied. The PLIP and LUNA papers [17, 18] provide methodological background; report the actual DockLens version and profile used. Cite an original engine as executed software only if it was separately run.

The exporter preserves original coordinates without automatic fitting or periodic-boundary correction and writes available source connectivity as `CONECT` records. It rejects overlapping/empty groups, covalent bonds between receptor and ligand selections, missing element identities, and atom/residue fields that cannot be represented faithfully in PDB. Re-export is required if source files change after loading.

PDB does not reliably encode ligand bond orders, aromaticity, or all formal-charge information. Review ligand chemistry and any downstream reconstruction, especially for unusual residues and metals. A hydrogen bond or contact found in one frame is an observation for that frame. Estimating occupancy requires an explicitly defined frame set, a consistent receptor/ligand pairing, identical detection rules, and a stated denominator; this single-frame interface does not perform that aggregation.

## 10. Use the CPPTRAJ script builder

CPPTRAJ processes trajectories using an explicit topology, atom masks, and ordered commands [9]. Its selection syntax differs from MDAnalysis syntax.

1. Open **Analysis > CPPTRAJ Script Builder**.
2. Choose a template: **RMSD**, **RMSF**, **H-bonds**, **Strip water**, or **Clustering**.
3. Choose **Insert**. This replaces the editor contents with the selected template; save any previous custom script first.
4. Replace example paths such as `topology.parm7` and `trajectory.nc` with matching files readable by CPPTRAJ.
5. Replace residue masks such as `:1-999@CA` with a selection appropriate for the actual topology. Review water and ion names before stripping.
6. Set output paths deliberately. On Windows, scientific commands run in WSL, so script paths must be valid there, for example `/mnt/c/MD/study/rep01/...`.
7. Choose **Working folder for relative script paths**. Review the CPPTRAJ executable and Conda environment in Preferences; these settings are shared with the builder.
8. Review the complete script, including the final `run` command. Save a copy with the project.
9. Choose **Run CPPTRAJ**, read its output, and inspect the generated files. Execution runs in the background. Wait for completion before closing or replacing the session; the builder does not cancel a running external command. A displayed template alone is not an analysis result.

Use absolute input and output paths when the working directory is uncertain. The builder does not automatically convert a GROMACS topology into an AMBER `parm7` file. For RMSF, establish an alignment protocol before calculating fluctuations; editing only the output filename does not supply that protocol. Contact, hydrogen-bond, and clustering parameters must be reported with the results.

## 11. Run MM-PBSA or MM-GBSA

The setup dialog can execute `gmx_MMPBSA` in the configured scientific Conda environment. End-state methods require an explicit receptor/ligand partition, compatible topology, a selected snapshot interval, and review of solvent/entropy choices [10]. Install the external program and its required tools before using this route; follow the official [gmx_MMPBSA workflow](https://valdes-tresanco-ms.github.io/gmx_MMPBSA/dev/getting-started/) for the installed version.

1. Prepare a working folder containing `topol.top`, its topology include files, and `index.ndx`. Confirm that the index defines the intended receptor and ligand groups for this exact system.
2. Choose **MM-PBSA / MM-GBSA setup** in **Analysis**.
3. Review **Complex structure (.tpr)** and **Trajectory**. These paths can be prefilled from Analysis but must match the working topology and index.
4. Set **Topology working folder** to the folder prepared in step 1.
5. Enter the distinct numeric **Receptor index-group ID** and **Ligand index-group ID** from the actual index. The displayed defaults are not recommendations and cannot be assumed correct for a new system. Confirm group composition, not only the group number.
6. Choose **MM-GBSA** or **MM-PBSA**. For GB, choose the intended IGB model from 2, 5, or 8. Set **Salt concentration (M)**; PB input uses the corresponding ionic-strength keyword rather than a GB model keyword.
7. Set **Start frame**, **End frame**, and **Interval** within the available trajectory. These frame numbers are one-based and differ from the zero-based frame inspector.
8. Choose **Per-residue decomposition** if it is part of the protocol. For **Entropy correction**, choose **None** or **NMODE**. NMODE uses the same requested frame window and interval and can be computationally expensive. Alanine scanning and quasi-harmonic entropy are not configured by this dialog.
9. Choose **Preview Input File** and inspect the generated namelist. A preview does not execute a calculation.
10. Choose **Run MM-PBSA / MM-GBSA**. The calculation runs in the background. Keep the dialog open until it finishes; the dialog blocks closing while its worker is active and does not expose an immediate cancellation control.
11. Read the completion/error message and inspect the new `mmpbsa_<identifier>` directory within the working folder. It stores `MMPBSA.in`, `execution.log`, `mmpbsa_manifest.json`, and the generated `FINAL_RESULTS.dat`/CSV outputs. Decomposition outputs are available when produced by the requested calculation.
12. Confirm the recorded exit status and actual numeric results before reporting an estimate. Preserve the input topology, index, includes, trajectory, and manifest together.

The manifest records the command, selected options, environment name, and hashes of the directly supplied inputs. Topology include dependencies remain in the original working folder and are not recursively hashed by this calculation's manifest. Retain them separately; the result directory alone is not a complete reproducibility archive.

Report MM-PBSA/MM-GBSA values with their protocol and limitations. A calculated end-state estimate is not an experimental dissociation constant, an inhibitory concentration, or evidence of biological efficacy. The **End-Point Free Energy** page described next remains a configuration preview; execution is provided by the Analysis setup dialog.

## 12. Use the configuration preview pages

Several advanced pages preserve proposed settings and produce readable previews. They carry **Configuration preview only** and **Preview configuration** labels. They do not execute the advertised scientific operation or create the requested output simply because fields were completed.

| Page | Procedure | Result of the preview |
| --- | --- | --- |

## 13. Export evidence and prepare a publication

### 13.1. Export an evidence bundle

1. Finish or stop the relevant calculations and inspect their outputs.
2. Save the session. Keep actual analysis results in the project folder if they should accompany the project evidence.
3. Open **Reports & Export** and choose **Export evidence bundle**.
4. Select the destination folder and wait for the export to finish. A new `moldynstudio_evidence_<timestamp>_<identifier>.zip` is generated.
5. Read `README.md` and `evidence_manifest.json` inside the ZIP. The manifest lists relative paths, sizes, SHA-256 digests, recorded stage states, and whether each recognized artifact was copied.
6. Inspect `files/` for included text inputs, topology includes, logs, tabular outputs, and recognized JSON metadata. Text artifacts above 16 MiB and binary simulation files are hashed but not copied.
7. Archive original XTC/TRR/DCD/NC trajectories, TPR, EDR, CPT, and external inputs separately. The evidence ZIP cannot resume a simulation by itself. Only artifacts within the selected prepared project and recognized by the exporter are indexed; inspect the inventory before treating it as complete.

An evidence bundle documents available files and metadata. It does not run missing analyses, generate favorable results, or certify scientific validity. Preserve original results and report unfavorable or failed checks. Runtime package versions in the bundle describe the export host; original calculation details remain in execution manifests and logs. Those original files can contain local paths and usernames, so review their contents before public deposition.

### 13.2. Reproducibility checklist

Before submitting a manuscript, verify that its methods and archived files identify:

- MolDynStudio source version/commit, platform, GROMACS executable/version, and resolved dependencies.
- Original structure identifiers/files, biological assembly, structure edits, ligand identity/stereochemistry, protonation states, net charges, and treatment of missing residues/cofactors.
- For repaired structures, the original and candidate hashes, selected conformers, explicit atom removals or residue conversions, approved sequence mapping/gaps, modeled coordinates, reconstruction versions/seed, and unresolved parameter requirements.
- Exact protein, ligand, water, and ion parameters; charge-generation method; and force-field package/version.
- For MATCH ligands, the reviewed chemical state, service session/method, submitted and returned MOL2 files, raw parameters, cache hashes, ParmEd version, conversion evidence, retained copy count, and explicit compound exclusions.
- Box geometry, padding, particle counts, salt concentration, neutralization, and periodic-boundary treatment.
- Actual MDP inputs for every stage, restraint definitions, thermostat/barostat settings, cutoffs, constraints, timestep, and requested versus completed durations.
- Independent replicate design, random seeds or generated run inputs, interruptions/restarts, equilibration exclusion, and sampled frame interval.
- Each analysis selection, fitting/reference convention, units, thresholds, software versions, and retained output tables.
- Time-correlation treatment, uncertainty estimation, replicate disagreement, failed runs, exclusions, and sensitivity checks where applicable.
- Frame provenance and receptor/ligand pairing for DockLens inspection, plus chemistry reconstruction limitations.
- A data/software availability statement and the papers for tools and methods actually used.

The checklist follows the scope of established molecular-simulation and sampling guidance [12, 13]. MolDynStudio does not automatically produce all of these records. A software paper also requires defined validation datasets, reproducible benchmarks, and a clear comparison with existing tools; adding interface features alone does not establish methodological novelty.

## 14. Troubleshooting

| Symptom | Check and next action |
| --- | --- |
| **Begin** is unavailable | Read the launcher status for WSL2/Linux, Conda, and GROMACS. Resolve the failed component and choose Re-check. |
| `HCS_E_HYPERV_NOT_INSTALLED` or virtualization unavailable | Enable the required firmware/Windows virtualization features, restart, and verify WSL separately before retrying. |
| GROMACS cannot be found | Check the selected binary and Conda environment; verify that the executable runs in the same native Linux/WSL environment used by MolDynStudio. |
| A native library import fails or the application crashes | Run the local runtime self-check described in section 2.5. Retain its JSON and log, including the failed or incomplete probe; also check external GROMACS separately. |
| GPU mode fails | Inspect the selected GROMACS build's reported GPU support. Use a supported build or an appropriate CPU mode. |
| Force field not found | Install the required parameter directory in the scientific environment; use explicit download/import for the supported CHARMM36m package. |
| Automatic ligand preparation is blocked | Check force-field family, covalent connections, elements, ligand chemistry, protonation, and net charge. Use a specialized parameterization workflow for unsupported chemistry. |
| CHARMM ligand chemistry review is missing | Supply one explicit-hydrogen MOL2, review its protonation and Expected net charge, then select the chemistry-review checkbox. Reopening a project or changing ligand inputs clears that confirmation. |
| SwissParam requests upload consent | A verified cache for this exact input was not found. Review the public service terms and select Allow uploading this ligand MOL2 to SwissParam if a new request is intended. Protein files are not uploaded. |
| SwissParam changed the ligand or net charge | Preserve the rejected response and inspect hydrogen count/attachment, names, elements, bond orders, and charge. Do not accept a different chemical state merely because parameter files were returned. |
| Complex extraction rejects a ligand copy | Check exact heavy-atom names/elements against the MOL2, complete ligand composition, resolved alternate locations, and any inter-residue covalent link. All selected copies must satisfy the same chemical contract. |
| An extra compound blocks preparation | Review whether it belongs in the scientific model. Supply a separately validated workflow if it must remain, or name an intentional omission under Exclude extra compounds. Do not exclude protein, water, or the selected ligand. |
| CHARMM conversion rejects a directive or parameter | Read the reported unsupported term or missing parameter. The restricted adapter does not silently remove patches, NBFIX, CMAP, or polarizable terms. Use a validated external preparation route for that model. |
| Repair asks for a FASTA mapping | Select both FASTA chain and FASTA record, then choose Inspect structure again; clear Optional FASTA only if deposited sequence information is sufficient for the intended plan. |
| A numbering gap appears but no reconstruction is offered | Check the aligned sequence, insertion codes, construct boundaries, and modified residues. Missing author numbers alone do not establish missing coordinates. |
| Repair modeling backend is unavailable | Install the current GUI requirements in the Python environment running MolDynStudio. PDBFixer/OpenMM inside WSL alone do not support the native Windows repair worker. |
| Reconstruction fails or times out | Read the retained reconstruction request, result when present, and engine.log. Review input atom identities, approved gaps, and the first error before creating a new attempt. The native worker has a 600-second timeout. |
| Candidate is structurally blocked | Read all repair-report findings. Resolve incomplete standard residues, incompatible conformers, ambiguous reconstruction, or severe overlaps explicitly; do not delete distinct atoms solely to silence a contact warning. |
| Repaired structure cannot be adopted or prepared | Check whether the original PDB/FASTA, candidate, report, or recorded artifacts changed or moved. Generate and review a new candidate from the intended inputs rather than editing stored hashes. |
| An older repair session lacks an approved report digest | Reopen Inspect / repair structure, review and adopt the verified candidate again, then save the session. A report path alone does not establish prior approval. |
| Candidate is coordinate-ready but still requires parameters | Supply a separately validated model for every retained covalent adduct or modified residue. Structural reconstruction does not create those force-field parameters. |
| Preparation fails after writing some files | Preserve the log. Resolve its first concrete error and rerun in a clean, dedicated project folder so partial and previous artifacts are not confused. |
| **Run All** or **Resume** is disabled | Read Prepared run review. Undo pending MD Setup changes or prepare again, then confirm that the manifest and prerequisite artifacts are valid. A filename alone is insufficient. |
| Setup comparison is not recorded | This older project lacks a prepared snapshot. Review the recorded inputs and all four actual MDP files; current GUI values are not proof of its preparation choices. |
| Environment check fails or a run cannot start | Use Settings to check the recorded GROMACS executable, Conda environment, and resource selection. Open project / logs to inspect the first concrete stage error. A compiled GPU backend alone does not prove GPU use. |
| Checkpoint append fails | Restore a consistent production checkpoint/output set. Do not combine files from different runs. Inspect GROMACS' append/checksum error. |
| `No module named MDAnalysis` or `mdtraj` | Install the required package in the Python environment running the GUI, or use a distribution containing it. The WSL scientific environment and Windows GUI environment are separate. |
| Topology/trajectory atom mismatch | Pair the trajectory with its original topology, or create matching reduced files with identical atom order. |
| 3D panel is empty after reopening a session or completing production | Check the restored/offered source paths and choose **Load 3D view**. Sources are not opened automatically by these handoffs. |
| 3D loading fails or navigation is unavailable | Read the panel status for the source/reader/selection error. A structure without a trajectory has only one coordinate frame and no simulation time or playback. |
| Preparation, Run, or a session switch waits for 3D work | Pause playback and let the current read/export finish. Preparation and execution release the idle reader; reload it afterward. |
| Atom selection is empty | Check residue/atom names and the backend's selection syntax. `resname LIG` is an example, not a universal ligand name. |
| RMSD/RMSF or shape measures are unexpectedly large | Inspect periodic images, molecules split across the box, atom selection, reference frame, and alignment before interpreting the values. |
| SASA cannot be compared with a GROMACS value | Check selected atoms, whether surrounding atoms were removed, probe radius, algorithm settings, and area units. |
| PCA requests too much memory | Use a smaller scientifically justified atom selection, such as C-alpha atoms. Record that choice. |
| QC files have no time unit | Preserve XVG axis metadata or provide a documented CSV time column. Unknown units should not be relabeled by assumption. |
| DockLens export or launch fails | Check disjoint nonempty selections, explicit elements, periodic-image review, a writable output folder, and a compatible DockLens executable. |
| A preview produced no output files | Check the page's capability label. Configuration previews do not launch calculations. |
| Opening an `.mds` file produces no trajectory | Restore the referenced project outputs or load a real topology/trajectory pair. Session state is not trajectory data. |

For a reproducible issue report, retain the application version, platform, relevant settings, exact error, and the preceding log context. Include the smallest shareable input that reproduces the issue and state which steps were executed. Avoid editing the only copy of the failed run while diagnosing it.
